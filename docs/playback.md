# 回放的时间语义

播放器基于读者的一次索引快照工作，循环、变速、跳转都不会改变底层数据。

## 节奏

- 每条消息相对计划首条消息的时间差为 `stamp - baseStamp`；
- 实际等待 = 时间差 / `Rate`，`Rate=1` 即原始节奏，`Rate=10` 为 10 倍速；
- `Rate<0` 表示尽快模式（不睡眠），用于确定性测试；
- 运行中 `SetRate` 从当前消息重新锚定时间基准，不会补发或重发。

## 区间与循环

- `Options.Span` 为半开区间 `[Start, End)`，在构建计划时裁剪；
- `Loop=true` 时播完一轮回到计划起点；每个事件带 `Loop` 轮次号和计划内 `Index`；
- 轮次边界只衔接首尾，不重复最后一条也不漏第一条。

## 暂停 / 恢复 / 跳转

- `Pause` 后不再投递任何消息；
- `Resume` 会把暂停时长补进时间基准，恢复后消息间隔仍保持录制时的相对节奏；
- `SeekTo(pos)` 跳到计划内绝对位置：已发送的消息不重发、目标之前的消息不补发、
  目标及之后按顺序发送，不倒置；`SeekStamp(t)` 跳到第一个 `stamp >= t` 的位置；
- 越界跳转返回错误。

内部用“代次（generation）”令牌保证：任何等待中的旧发送动作，在暂停、
恢复、变速或跳转后都会被判定为过期而放弃，从机制上避免重复、漏发与乱序。

## 边录边读

读者看到的是构建快照那一刻已提交的数据；写者正在写的帧由段尾 EOF 标记遮挡，
不会被半成品读入。录制进行中，已打开的读者重复查询结果保持一致；
调用 `Refresh()` 后才会看到新提交的消息。

## 验证方法

```bash
go test ./... -count=1 -v          # 查看每个业务与用例的中文覆盖日志
CGO_ENABLED=1 go test ./... -race  # 竞态检测（并发录制/读取、回放控制）
```

测试日志按 `[业务:...] 用例[...] 通过：...` 输出，覆盖：

- 中断恢复：崩溃后完整消息可读、半截帧丢弃、恢复后续写；
- 损坏与空区间区分：空区间、`ErrNoBag`、`ErrCorruption` 三种情况；
- 定义演进：新增字段默认值/零值、删除/改名/改类型拒绝、写入侧严格校验；
- 时间戳：相同时间戳确定次序、乱序时间戳归位、话题+区间裁剪；
- 回放：原速/变速、区间、循环、暂停恢复、跳转、定义演进回放；
- 并发：多话题录制 + 多读者快照一致性、单写者锁、段滚动。

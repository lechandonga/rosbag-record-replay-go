# 消息定义兼容规则

消息负载按**字段名**编码（gob map），绝不按字段位置解析，因此字段顺序调整本身不影响数据。

字段支持类型：`string`、`int32`、`int64`、`float64`、`bool`。

## 允许的演进：纯新增字段

用新版本 schema 回放旧数据时，旧数据里没有的新字段按固定、可解释的规则补齐：

1. 新字段声明了 `Default`（JSON 字面量）-> 使用该默认值，回放事件的 `Notes` 标记 `Source="default"`；
2. 没有声明 `Default` -> 使用类型固定零值，`Source="zero"`：
   `string -> ""`，`int32/int64 -> 0`，`float64 -> 0.0`，`bool -> false`。

新增字段的 `Default` 无法按字段类型解析时，回放被明确拒绝，而不是悄悄给零值。

## 必须拒绝的演进

以下情况返回 `msgdef.IncompatibleError`，并在 `Reason` 中给出具体字段与原因，
播放器会在投递到该类消息时通过 `Player.Err()` 暴露：

- **删除字段**：录制时存在的字段在当前定义里消失；
- **字段改名**：改名等价于“删除旧字段 + 新增新字段”，旧数据无法证明新字段语义，拒绝；
- **类型改变**：同名字段类型不一致（如 `float64 -> int64`），不做猜测式转换；
- **类型名改变**：消息类型本身的名字不同。

## 写入时校验

- 消息缺少 schema 中任一字段 -> 拒绝写入；
- 消息出现 schema 未声明的字段 -> 拒绝写入；
- 字段值类型不符 -> 拒绝写入。

`schema.Fingerprint()` 基于字段名与类型（sha1 前 16 位）。帧元数据携带该指纹，
读者据此找到录制时的定义，再用上面的规则与“当前定义”做比对和投影。

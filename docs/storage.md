# 存储与索引布局

一个 bag 就是本地一个普通目录，不依赖任何 ROS 环境：

```
<bag-dir>/
  metadata.json        # 话题 -> 类型 -> schema 指纹登记表（原子 rename 写入）
  seg-00000.log        # 只追加段文件，可按大小滚动
  seg-00001.log
  lock                 # flock 排他锁：同一目录同一时刻只允许一个写者
```

## 段文件帧格式

所有多字节整数均为大端。单帧布局：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | magic `LOGB` |
| 4 | 1 | 版本（当前 1） |
| 5 | 1 | kind：1=schema 登记，2=话题绑定，3=消息 |
| 6 | 2 | 保留 |
| 8 | 8 | stamp（消息原始时间戳，纳秒） |
| 16 | 8 | seq（写者内单调递增的全局序号） |
| 24 | 8 | metaLen（gob 元数据长度） |
| 32 | 8 | bodyLen（消息负载长度） |
| 40 | 32 | sha256(meta + body) |
| 72 | 8 | commit，值恒等于整帧字节数（完整性自检） |
| 80 | metaLen | gob 元数据（话题名、类型名、schema 指纹，schema 登记帧含完整定义） |
| 80+metaLen | bodyLen | 消息负载（`msgdef.Encode` 的原始字节，按字段名编码） |

段文件**最后 8 字节是 EOF 标记**，标记之前才是“已提交数据”。写入一帧的顺序是：

1. 把整帧 `pwrite` 到 EOF 标记之后（对读者不可见）；
2. `pwrite` 把 EOF 标记移动到帧尾之后，整帧原子变为可见；
3. 默认每条消息 `fsync`（`SetSyncEachWrite(false)` 可关闭以换取吞吐）。

## 崩溃恢复语义

读者只前向扫描 EOF 标记之前的数据：

- 帧头 + 校验和 + commit 全部吻合才算一条完整帧；
- 已提交区中间出现对不上的帧 -> `ErrCorruption`（硬损坏），查询直接失败，绝不静默漏掉一段；
- 段尾部存在无法闭合的字节 -> 崩溃时正在写的**半截帧**，记为 `partial_tail_recovered` 并安全丢弃；
- 写者重新打开目录时，扫描全部段、把最后一段截断到最后一个完整帧边界，之后可无缝续写。

因此：进程异常退出后，已经提交的消息一条不丢，写了一半的消息绝不会混进查询结果。

## 索引

索引在打开时由段文件重建（顺序扫描），是内存中的有序 `Entry` 列表：

- 排序键为 `(stamp, seq, segment)`；
- 乱序时间戳会被归位；相同时间戳用 seq 保证确定先后，顺序不依赖 map 或位置；
- 每个 `Entry` 记录段文件名与消息负载偏移，可 O(1) 定位并直接读取负载；
- 支持按话题集合 + 半开时间区间 `[Start, End)` 查询。

## “损坏”与“本来没有数据”的区分

- 目录不存在 / 从未产生段文件 -> `ErrNoBag`；
- bag 正常、区间内无消息 -> 返回长度为 0 的切片且 error 为 nil；
- 任一段存在硬损坏 -> `Query` 返回 `ErrCorruption`，避免把损坏伪装成空区间；
- `Reader.Health()` 可区分 `partial_tail_recovered`（可恢复）与 `corruption`（不可信）。

## 并发读写

- 写者持 `flock` 排他锁；第二个写者打开即失败。
- 读者数量不限，各自独立打开文件、构建自己的索引快照。
- 快照在两次 `Refresh` 之间内容固定；写者继续追加不影响已经打开的读者，读写互不干扰。
